# 病原体イラストの音声同期モーション

完成済み一枚絵を「背景とキャラクター／タイトル／個々の吹き出し／国試POINT」のレイヤーへ分ける。元画像の顔と日本語は勝手に生成し直さない。制作票と入力形式は `references/layer-manifest.md`、汎用FFmpeg組み立ては `scripts/render_layer_reel.py` を参照する。

## 1. 素材の確認

1. 元画像を原寸とスマホ縮小で見て、吹き出しを**読む順番**で番号付けする。既存の吹き出しと指定台本が一致しないときは、音声と表示の意味のずれを制作票へ明記する。医療内容を黙って変えない。
2. セーフマージンを設計する。一般的なプラットフォームUIを見越して主要文字は左右各90px程度以上、上方200px程度、下方300px程度を目安にし、投稿プレビューで重なりを確認する。元絵が横に広いなら、全体を縮小して収める。
3. 背景と人物を先に見せる**静止したbase.png**を用意する。元画像上のタイトルと吹き出し部分は、局所的な修復・背景の色を利用して隠す。マスクに髪や手が入る場合は、キャラクターを別レイヤーで上に戻す。初めのフレームを黒にしない。
4. 元のタイトルと吹き出しを、文字と輪郭ごと透明PNGへ切り出す。ぼけた矩形が露出したり、隣の髪や飾りを消したりしないようマスクを目視で補正する。位置と境界を記録する。国試POINTは必要なら別描画し、元絵の他の日本語は維持する。

## 2. 音声を先に確定

- ユーザー指定の声を最優先する。声の種類・バージョン・話者まで一致を確認し、利用不能なら**別の声で勝手に完成させず**ユーザーへ確認する。
- CoeFontが指定された場合は、承認済みのブラウザ操作でログインし、吹き出し1個につき1音声を作ってダウンロードする。パスワード・確認コードの入力はユーザー本人に任せる。音声が成功したことを個別のMP3と長さで確認し、ダウンロードのクリックだけで成功扱いにしない。
- 文字・語順は指定文を守る。略語は発音のためカナ読みへ調整しても表示文は書き換えず、医学的意味を維持する。句読点を調整したら試聴する。
- BGMは既定で入れない。声と競合しないごく小音量を明示希望された時だけ加える。

## 3. タイミングを決める

- 1080×1920、9:16、30fps、約40秒。背景と人物を0秒に表示。タイトルを初め低透明度・軽いぼかし・95%から、約1秒で鮮明な100%へ移す。
- 吹き出しは上から短く36px程度下降し、最後に減速して着地させる。位置関係で上から不自然なら左の吹き出しを左から、右を右から入れる。強い跳ね返り、勝手なカメラワークは使わない。
- **着地から約0.1秒後にその吹き出しの声を始める。** MP3実長を測り、前の発話が終わってから次の吹き出しを出す。「出る→読む→次が出る→読む」を守る。長い文に合わせて時刻を延ばし、声を急がせない。
- 最後約3秒に全要素を残し、国試POINTを大きく見せる。必要時は完成カード全体をわずかに縮小する。POINTと左右の説明をUIや顔に重ねない。

## 4. 書き出しと検品

マニフェストの例は `references/layer-manifest.md`。音声なしの最終書き出しを禁止する。レイヤー化の品質を冒頭・各着地後・最終3秒のフレームで確認してから、同梱の汎用スクリプトを利用するか、同等のFFmpeg・HTML等で実装する。

```bash
python3 scripts/render_layer_reel.py project.json finished-reel.mp4
ffprobe -v error -show_entries stream=codec_name,codec_type,width,height,r_frame_rate -show_entries format=duration -of json finished-reel.mp4
```

- H.264映像、AAC音声、1080×1920、30fps、faststart、長さ、**音声ストリームが実在すること**を確かめる。
- 冒頭を含む全編をデコードし、黒画面、文字切れ、顔の変形、吹き出し出現前の音声、発話中の次の出現、語尾の欠落、最後のカードの表示不足を確認する。音量が小さすぎずクリッピングもないことを聴いて確かめる。
- 最終版MP4を保存して渡す。必要なら制作プロジェクトと静止画の中間成果を別に渡すが、ユーザーへ無音プレビューを「完成版」と呼ばない。
