# 1部4枚の共通データ形式 v1

[JSON Schema](manifest.schema.json) が型と必須項目を定義する。[記入例](../examples/synthetic.json) は水色の下線を使う前半4枚・58秒の仮想データ。後半も同じ形式で、時刻を0から始める。すべての時刻は最終動画の先頭からの整数ミリ秒、区間は開始を含み終了を含まない。実測は最終音声と最終動画を同じ再生起点に合わせて採る。

| 欄 | 採取するもの |
|---|---|
| `part / duration_ms / speed` | 部の名前、最終動画の全尺、実効読み上げ速度。TTSと編集の両方で速度を変えたときは合成後の倍率を書く。初稿の既定は1.3倍。実測では倍率を明記する。 |
| `slides[]` | 表示順の4枚。原図の識別名・ファイル名・表示の開始と終了。各原図は次へ切り替わるまで表示する。 |
| `sentences[]` | ページの候補文。各文に固有の `id`、構造上の `kind`（heading/body）、`role`（conclusion＝結論、mechanism＝発生機序、observation＝観察、context＝前提、detail＝補足）、必読かを示す `essential`、単独で部を始められるかを示す `can_open` を付ける。任意の `requires` は、先に読む必要がある文IDの配列。 |
| `lines[]` | 一文を原図の改行順に登録する。一行ごとに固有の `id`、原文 `text`、文字矩形 `box=[左,上,右,下]`。座標は変換前の原図のピクセル。同じ文字列でも別の出現には別IDを使う。一行内を複数の短句で追う場合は、各短句を固有ID・実座標・実時刻の単位として並べる。 |
| `lines[].spoken` | 任意。原図の意味と照合して承認したひらがな読み・言い換え。省略時は原文と照合する。否定、程度、数値、単位を保つ。複数行にまたがる言い換えでは各句が指す文字範囲を先に対応づける。 |
| `plan[]` | 読む文IDを台本順に並べる。選んだ文の全行を読む。不要な例は文ごと外す。 |
| `speech[]` | 最終音声を聞き取った順の発話ID、聞こえた文 `transcript`、原図上で対応する `line_id`、発話の `start_ms / end_ms`。録音を聞いて採るか、短い句単位のアラインメントを試聴補正する。書き起こしは原文または承認した読みと比べる。空白と「、。」を除き、日本語の否定、符号、小数点などを残す。 |
| `bridges` | 任意。原図に対応しない短いつなぎを「発話ID → 承認した発話内容」で登録する。対応する発話だけ `line_id:null` とし、下線を付けない。通常の原文をここに移して検品を回避しない。 |
| `underlines[]` | 書き出し側で観測した下線。対応する `cue_id`、実際に印を付けた `line_id`、実測の `on_ms / focus_end_ms / off_ms`、完成した線の左端・中心の高さ・右端 `segment=[左,y,右]`、実際の `color`。原図座標に戻して記録する。 |
| `evidence / audio_timing / underline_timing` | 仮想試験は `synthetic / fixture / fixture`。実測は `measured` とし、音声は `final_audio_listening` または `reviewed_alignment`、下線は実際に描画したタイムラインの `render_log` または最終動画をフレームで調べた `frame_review`。 |
| `media` | 実測時は `audio` と `video` それぞれに `path` と小文字64桁の `sha256` を記録。相対パスは対応表ファイルが基準。最終動画から直接聞き取った場合は両方に同じMP4を指定できる。素材を入れ替えたら時刻も採り直す。 |
| `listenability` | `unchecked / clear / revise`。実測で `clear` を付けるのは最終速度で聞き取りを確認した場合。聞きにくい場合は台本を短くして再収録する。 |

## 色と同期の判定

- 色の優先順は `underline_colors.heading` または `.body` → `.all` → V3既定（headingは `red`、bodyは `yellow`）。全体を水色にする例は `"underline_colors":{"all":"#80DEEA"}`。本文だけなら `{"body":"#80DEEA"}` とする。色名はスキーマの列挙値、指定色は `#RRGGBB` でも渡せる。下線の記録も同じ表現にそろえる。半透明合成後の画素値ではなく描画色を記録する。
- `on_ms` はその行の線が現れた時刻。`focus_end_ms` はその行が読み上げ中の対象でなくなる時刻（フェード開始や次行へのフォーカス移動）。左から右に線を伸ばし終えた時刻とは区別する。`off_ms` はフェードも終わり、線が消えた時刻。瞬時に消す場合は後ろ2時刻を同じにする。見分けられない時刻は推定で埋めず、未確認として残す。
- 発話開始と `on_ms`、発話終了と `focus_end_ms` を個別に比較し、**絶対差150 msまでを合格**とする。共有V3の開始目標を採用し、追加検品では終了側も同じ幅で照合する。例として、発話が12,000 msに始まる行は12,150 msの表示で合格、12,151 msで `START_DRIFT`。完全消去時刻を発話終了と直接比較しない。
- 複数行の同一文は、それまでに引いた行を文末まで保持できる。消去は文末から最大300 msまで、かつ次の文・つなぎの開始およびページの終了まで。次の文を読み始めても前文の線が残れば `STALE_UNDERLINE`。
- 原図直下の位置検査は、線の中心が文字矩形下端から文字高の半分（最低2 px）以内で、両端がそれぞれ行幅の20%以内にあるかを確認する。この数値は追加ツールの位置判定の目安。座標は文字領域の実寸を取り、ズームやレターボックスを逆変換する。規則的なログだけでは、変換ミスや図の取り違えを見落とせるため、最終映像で照合する。
- 計画と発話の順序、文字列、線の対象ID、座標、表示区間を独立に比較する。必読文と前提の抜けは不合格。結論・発生機序・観察ポイントより補足を優先している場合は、該当文を確認候補として `notes` に示す。医学的な重要度、言い換えの妥当性、聞きやすさは制作担当が判定する。

## 実行

Python 3.9以降で、このスキルのディレクトリから実行する。Windowsで `python` が使えない場合は `py -3` に読み替える。実測モードはPATH上の `ffprobe` で最終メディアの長さとストリームを確認する。仮想試験にはPythonと下記の依存パッケージを使う。

```sh
python -m pip install -r requirements.txt
python scripts/check.py examples/synthetic.json
python -m unittest discover -s tests -v
```

前半・後半をまとめて検品する例。各部の尺と結果を個別に返す。どちらか一方でも失敗すれば全体の終了コードが非ゼロになる。

```sh
python scripts/check.py --require-measured front.json back.json
```

| 結果 | 意味 |
|---|---|
| `SYNTHETIC_PASS` / `SYNTHETIC_FAIL` | 仮想入力に対する判定。実測専用オプションを付けた仮想入力は常に不合格。 |
| `MEASURED_PASS` / `MEASURED_FAIL` | 実測として提出された記録の照合、最終素材の指紋・尺・ストリームの判定。自動の音声認識、動画の画素解析、全編試聴の代行は含まれない。 |
| `INPUT_ERROR` | JSON、必須項目、型、時刻取得方式などの不備。 |

終了コードは合格0、検品不合格1、入力不備2。同梱のテストは仮想データ・ダミーファイル・模擬応答のみを使う。発話ごとの実測値を用意できない場合は実音声による同期を未検証と報告する。
