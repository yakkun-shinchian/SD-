# インフォグラフィックV3（略称：インフォV3）

## 基本方針

- 「Infographic V3｜蛍光ペン・囲み分けルール」を標準として適用する。赤は見出し、黄は本文、緑の音声同期囲みは現在地を示す。色をむやみに混ぜず、色を見れば役割が分かるよう固定する。
- 本スキルは独立したV3として使用する。Info2・I1・Instagram V6自体を変更しない。V3制作時に旧方式と矛盾する場合は本仕様を優先し、今回のユーザー指定を最優先する。
- 原図・台本・尺・音声指定を確認する。既に明確な指定は聞き直さない。指定がなければ縦9:16、1080×1920、30fpsのMP4、60秒を初期案とし、読む時間を優先して構成する。

## 1．全文を追い、一文ごとに消す下線

- 台本で読み上げる箇所は一部の単語だけでなく、対応する一文全体を下線で追う。台本と原図の対応を先に記録し、原図に存在しない文を勝手に追加したり、無関係な文章に線を引いたりしない。
- 下線の蛍光ペンは、大見出し・中見出し（文字色ではなく構造上の見出しで判定）に赤、通常の本文・説明文に黄色のみを使用する。本文の重要語も赤に変更しない。青・緑は下線に使わない。優しい半透明とし、動画内で配色を統一する。濃いサインペン、細すぎる線、不透明な塗りつぶしにしない。太さ・透明度は背景と文字サイズに合わせ、文字を隠さず認識できる下線にする。
- 発話の進行に合わせて左から右へ滑らかに引く。一文を読み終えたら、その文の下線を消してから次の文に進む。文字と原図は残す。
- 複数行にまたがる一文は読む順に各行へ線を引き、一文の終了時にまとめて消す。改行だけで意味のつながる文を分断しない。
- 演出回数のノルマを設けず、読み上げ箇所を漏れなく追うことを優先する。過去の下線は積み重ねない。

## 2．説明のまとまりごとに、少ない回数でゆっくりズーム

- 原図の一部を別画面に置き換えず、一枚の原図への連続したカメラ移動として見せる。
- カメラは一文単位で動かさず、関連する複数の文・図を「一つの説明のまとまり」にまとめる。重要なまとまりへ一度ズームインしたら、その説明が終わるまで同じ画角を保つ。
- 次の説明が近くにある場合は、拡大倍率を保ち、ゆっくりパンして直接移行してよい。各文・各項目で全体表示へ戻る旧ルールは廃止する。
- 全体表示は冒頭の位置把握、大きな話題の切替、終わりの整理など、必要な場面に絞る。全体への復帰を毎回必須にしない。
- ズームイン・ズームアウト・パンは緩やかに加減速し、急な往復や細かな倍率変更を避ける。目安は一移動0.8〜1.5秒。固定回数のノルマを設けず、説明中の安定した画角と読みやすさを優先する。
- 文字・図・下線が見切れる前に倍率を止め、読ませる情報を移動中に通過させない。尺が短い場合は移動を速める前に移動回数を減らす。
- 下線は一文ごとに引いて消す動作を維持する。各下線の切替でカメラを動かす必要はないが、カメラは現在の発話対象を必ず画面内に保持する。対象が画角外へ移る場合は次の発話までにパンする。

## 3．重要箇所を柔らかい丸・矢印で示す

- いま読み上げている箇所を緑の半透明の蛍光ペンで囲み、実際の発話進行に同期して次の箇所へ移す。前の現在地囲みは消し、現在地を一つに絞る。この現在地表示は形や大きさにかかわらず緑を優先する。
- 重要箇所を示す補助的な囲みは、小さい丸・丸っぽいコンパクトな囲みを緑、大きい丸・細長い楕円を青に固定する。大きい丸は青を優先する。赤・黄色の丸は使わない。
- 現在地の緑囲みと補助的な青囲みは用途を区別し、同じ対象に不必要に重ねない。
- 丸はパッと素早く完成させる。描画時間の目安は0.15〜0.3秒とし、一文の長さに比例してゆっくり描かない。完成後は対応する説明が終わるまで見せる。丸の速さとカメラ移動の緩やかさを別々に制御する。
- 丸は対象の外側に余裕を持たせ、文字を横切らない。淡くても見える太さ・透明度に調整する。
- 「ここが重要」と示す箇所には必要に応じて矢印も使い、先端を正確な対象へ向ける。
- 丸と矢印は該当する説明に合わせて表示し、その説明が終わったら消す。過去の印を積み重ねない。
- 下線・丸・矢印の過剰な同時表示を避け、今見る主対象を一つに絞る。回数のために意味のない印を追加しない。

## 4．原図・音声・画角を保持

- 原図を実際に開き、文章・図・写真・ラベル・配置を保持する。強調は別レイヤーで重ね、原図と同じカメラ変換を適用して位置ずれを防ぐ。
- 薬剤写真など実物の見た目を創作・再生成しない。内容の修正依頼は演出追加と分けて扱う。
- 全体表示で左右の文字を切らず、縦横比を歪めない。原図の比率と出力が異なり全内容保持と余白なしを両立できない場合は制約を伝える。
- 音声がある場合は取得した実際の発話時刻に同期する。指定の声を無断で別の声に代用しない。音声未取得なら同期済みとは報告しない。
- 無音指定では音声を加えず、台本の読む順序と読める時間に合わせる。指定尺に収まらなければ、無断で文を落とさず必要な調整を伝える。
- キャラクター・吹き出し・追加字幕・CTAは指定がなければ加えない。

## 制作と検収

1. 原図・台本を対応づけ、関連する説明をまとまりに分け、その中に一文単位を配置する。
2. 各文の開始・終了時刻、各行の座標と描画順、色、消去時刻、音声同期する現在地の緑囲み、形・大きさで色を決めた補助の丸・楕円・矢印の対象と表示区間、まとまり単位のカメラ範囲・保持区間・緩やかな移動区間、必要な全体表示区間を記録する。
3. 一文単位の下線と説明箇所単位のズームを別々に制御し、発話または無音用の読む時間に合わせて合成する。
4. 書き出し映像で全文の強調漏れ、前文の線の消し忘れ、複数行のまとめ消去、不要なズーム往復がないこと、まとまり内での画角保持、緩やかなパン、見出しの下線が赤・本文の下線が黄であること、現在地の緑囲みが発話に同期して移動すること、小さい丸・丸っぽい囲みが緑、大きい丸・細長い楕円が青であること、囲みが素早く完成すること、丸・矢印の消去、文字の見切れ、同期・位置ずれを確認する。
5. 解像度・縦横比・尺・音声の有無・再生可能性を確認する。実際に行った検証だけ報告し、完成動画と再編集用データを保存して提示する。


## 5．読み上げ・蛍光ペン・ズームを一致させる必須手順

- 三者は同じ対応表を参照する。完成音声の実測時刻、実際に発話する語句、対応する原図上の文字列、原図座標の各行矩形、見出し／本文、太さ・色、表示・消去時刻、対象が収まるカメラ範囲、確認方法を一組にする。発話と原図の言い換えも意味を確認して対応づける。
- 音声を先に確定する。無音カット・連結・速度調整後の音声に対し、語または短い句の時刻を音声認識のアラインメントまたは試聴で取得する。区間の等分、文字数比、予定台本の秒数だけで時刻を決めない。時刻不明は未確認として残し、推測で同期済みとしない。
- 原図を実際に開き、各行の文字位置を目視確認する。OCRは補助にとどめる。同じ語が図と表の両方にある場合は今回読む出現箇所を一つに決める。原図に対応箇所がない補足説明では無関係な文を引かず、直前の関連対象を表示するか蛍光ペンを消す。
- 黄色は今読んでいる語句・説明行だけを追う。隣の行、未読の行、次の項目へ先走らない。複数行は実際の改行位置で分割し、発話順で引く。描画は左から右へ0.2〜0.4秒を目安とし、短い発話では発話区間内に収める。終了後0.15〜0.3秒で消し、次の行に誤って残さない。
- 赤は大見出し・中見出しだけに使う。本文の略語・重要語・表の項目名を見出し扱いして赤にしない。指定見出し一覧がある場合はホワイトリストとして固定する。「赤と黄だけ」と指定された動画では、既存の緑の現在地囲みと青の補助囲みも無効化する。
- 蛍光ペンを細い罫線にしない。初期値は対象文字高の0.45〜0.65倍の太い半透明帯、透明度30〜45％とし、文字の下半分〜直下に置く。赤・黄色とも最終出力で確認し、隣の行にはみ出す場合は位置・太さを調整する。「太く」の修正では前版の太さも記録して増やす。文字を読めることを優先する。
- 元画像・線・囲み・矢印に同一の座標変換を適用する。カメラを別の手入力タイムラインで漂わせない。対象矩形と読みやすい余白から画角を求め、現在読む行の全文が画面内に入る倍率に制限する。110〜125％は目安であり、文字を切るための必須倍率にしない。
- 同じ説明ブロック内はカメラを保持する。対象が変わり必要な場合だけ、次の発話開始に間に合うように移動し、読む間は安定させる。字幕・絵文字・追加注記で対象を隠さない。原図を改変せず、最後に全景へ戻す指定も守る。

### 同期検収ゲート

- 書き出し動画を音声付きで全編確認する。各語句の開始・中間・終了と各パンの直前直後を重点確認し、発話対象、黄色の対象、拡大範囲の一致を記録する。静止画の確認だけでは音声同期の確認にならない。
- 発話開始と線の開始の差は目標±0.15秒以内、最大0.2秒を目安に確認する。自動時刻は正解と決めつけず、特に略語・英語・列挙・速度変更箇所を試聴で補正する。実測・試聴なしにこの精度を達成したと報告しない。
- 一つでも別の行を強調する、赤が本文にある、対象が画角外、線が細すぎる、切替が発話に遅れる箇所があれば、対応表を修正して該当区間を再確認する。全編確認できない環境では検証限界を明示し「完全同期」と呼ばない。
- 修正依頼では旧版の推定時刻をそのまま再利用しない。完成MP4、音声、対応表、再編集用データを保存する。スキル更新のみの完了と動画の修正完了は分けて報告する。
