# インフォグラフィックM3

完成したインフォグラフィックをそのまま使い、読み上げている既存文字を太い半透明の蛍光ペンで追う動画を制作する。2026年10月17日にユーザーが採用したパーキンソン病の改訂版を基準とする。具体的な数値と検証例は [references/production-pattern.md](references/production-pattern.md) を参照する。

## 読む順序と台本

1. 冒頭で原図の大見出しを読む。同時にその文字を赤で強調する。例えば「パーキンソン病」から始める。
2. 各章では必ず「中見出しの読み上げ＋赤い強調」を先に行い、その後に本文へ進む。見出しを黙って通過したり、赤い強調だけ省いたりしない。丸数字は章の識別に用い、番号を発声するかは自然さに合わせる。
3. 本文の重要な記載を原図の表現に沿ってできるだけ多く読む。読み上げた本文は黄色でたどる。強調字体やカード内の項目名でも、構造上の見出しでなければ本文として扱う。
4. ①など全体の理解を支える章には説明時間を多めに配分し、原因→変化→結果を伝える。パーキンソン病では、黒質のドーパミン神経が減る→線条体へのドーパミンが減る→運動調節が乱れる、という因果関係を伝える。別の疾患にはその病態に合った因果関係を使う。
5. 原図にない補足を読む場合は、関係のない文字を代わりに塗らない。略語の読み替えや接続語の追加は対応関係を明示する。医学的な追加・訂正が必要な場合は一次資料で確認する。
6. 修正依頼では、残すよう依頼された本文を勝手に削らず、大見出し・中見出し・説明を補う。

## 尺と声

- 約40秒は目標値として扱う。重要な見出しと説明を追加して収まらない場合、過度な早口にせず、延長する見込みを伝える。採用例は約58秒。40秒をすべての案件で58秒に変えるルールにはしない。
- 尺が厳密指定なら、必要な見出しを含む構成を先に決め、重要本文を選んで収める。理解できない高速音声や途中切断で調整しない。
- CoeFontの制作では共通スキル `coefont-new-project` を使用する。「声本」「汎用性概念」などの表記揺れは文脈から扱い、今回の指定声は「汎用式概念χ-soft-v2[最高精度] ¦CV:ろさちゃん Losa-chan -soft」。今後別の声が指定されたらその指定を優先する。
- 新規案件は専用プロジェクト、同一案件の修正は同じプロジェクトで管理する。実際の選択音声を確認し、完成音声を取得する。別音声に無断で代替しない。
- 音声を先に完成させ、最終速度の音声に対して同期を作る。速度調整後はタイムスタンプを取り直すか正確に変換する。

## 蛍光ペンと原図

- 原図の文字・絵・配置を保持する。既定では字幕、説明テキスト、絵文字、CTAを追加しない。
- 大見出しと章の中見出しは赤、本文は黄色にする。原図の文字色ではなく文章の役割で色を決める。緑の囲みや青い楕円は既定では追加しない。
- 文字のすぐ下の細い線ではなく、字面の下側約75〜85%に重なる太い半透明帯を描く。塗っても文字を判読できる濃さにする。
- 実際の改行と語句に合わせて原図上の矩形を登録する。折り返しは行ごとに分割し、別の行・図・隣のカードを塗らない。
- 読み上げ中の語句を左から右へ引き、読了後は短く消す。未読箇所の先塗りやマーカーの蓄積を避ける。
- マーカーと原図に同じ拡大・移動変換を適用し、ズームしても文字との位置関係を保つ。

## 同期とカメラ

1. 完成音声から単語または短句の実測タイムスタンプを得る。自動認識結果は原稿・音声と照合する。文字数による比例配分や均等割りだけで同期を済ませない。
2. 各マーカーに元の文字列、原図の座標、開始・終了時刻、見出し／本文の区別を記録する。
3. カメラは説明ブロック単位で穏やかに動かす。語句ごとのズームを避け、関連する説明は拡大したまま移動する。横並びのカードは横幅を広く保つ。
4. 前の語句が読み終わる前に次の画角へ移して、その文字を画面外へ出さない。間が短ければ広めの共通画角を使う。
5. 冒頭と最後は全体像を見せる。原図を無理に切らず、原則1080×1920、9:16、30fps、H.264映像＋AAC音声のMP4にする。

## 完了確認

- 大見出し→各中見出し→その本文の順序と、見出しに赤い強調があることを全章で確認する。
- 各マーカーの開始・中間・終了で、対象文字との重なり、画面内への収まり、行末までの表示を確認する。カメラ遷移中の切れも確認する。
- 原稿、実音声、タイムスタンプ、座標を照合し、誤読・読み飛ばし・先行／遅延を直す。
- 動画の音声トラック、尺、解像度、デコード成功を確認し、可能な環境では全編を音声付きで再生する。静止画やASRだけの検証を全編試聴済みと呼ばない。未確認範囲は正直に伝える。
- 完成MP4と再編集に必要な原稿、音声、同期データ、レンダリング情報を保存する。保存できた成果物だけを完成品として案内する。
