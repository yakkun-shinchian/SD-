# 完了前の証拠確認

「できた」という主張を、現在の成果物に対する新しい検証結果へ結び付ける。

## 手順

1. ユーザーの要求と、自分が完了として主張する項目を列挙する。
2. 各主張に対応する最小で直接的な検証方法を決める。
3. 対象の現在状態に対して検証を実行し、終了コード、件数、差分、表示結果などを確認する。
4. ファイルの存在だけでなく内容、計算の式だけでなく結果、テストの起動だけでなく合否を確認する。
5. 変更後の最終成果物を再度点検し、古い結果を使い回さない。
6. 要件ごとに、確認済み、未確認、失敗、対象外を対応付ける。
7. 証拠が十分な項目だけを完了と表現し、残作業と制約を明確に伝える。

## 安全境界

- 検証のために無関係なファイル変更、破壊的コマンド、外部送信を行わない。
- 実行できなかった検証を成功と扱わず、目視確認を自動テストと呼ばない。
- 一部成功を全体成功へ拡張しない。
- テスト結果やログを捏造せず、失敗や警告を省略しない。
