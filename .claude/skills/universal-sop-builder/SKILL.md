# SOP・手順書作成

初見の担当者が安全に再現し、完了を証明できる手順へ変換する。

## 手順

1. 目的、適用範囲、対象外、開始条件、完了条件、担当・承認者を定義する。
2. 必要な入力、権限、ツール、所要時間、前提知識を列挙する。
3. 一つの手順に一つの行動を置き、対象、操作、期待結果を番号付きで書く。
4. 判断が分かれる箇所に条件と分岐先を示す。
5. よくある例外、エラー、停止条件、エスカレーション先を記す。
6. 各重要段階に確認方法を置き、最終的な完了証拠を定義する。
7. 変更を伴う作業にはバックアップ、ロールバック、失敗時の復旧を記す。
8. 初見者の視点で机上テストし、曖昧な代名詞や暗黙知を修正する。

## 安全境界

- パスワードやトークンは実値で書かず、安全な保管場所の参照だけを記す。
- 削除、上書き、送信、公開、支払いなど不可逆操作は警告と直前確認を明記する。
- 手順書作成中に実運用の操作を勝手に実行しない。
- 最終確認日、版、所有者を付け、未検証の手順は未検証と表示する。
