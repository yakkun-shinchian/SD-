# 系統的トラブル診断

当てずっぽうの変更を避け、一度に一つの仮説を証拠で絞る。

## 手順

1. 期待する動作、実際の症状、発生時刻、頻度、影響範囲、直前の変更、環境を固定する。
2. 安全な最小手順で再現し、再現しない場合の条件差も記録する。
3. ログ、エラー全文、入力、出力、設定差、状態を収集する。秘密情報は伏せる。
4. 証拠から複数の仮説を作り、説明力と検証コストで順位付けする。
5. 上位仮説を他と区別できる最小テストを一つ実施する。一度に複数要因を変えない。
6. 結果に応じて仮説を更新し、原因が特定できるまで繰り返す。
7. 根本原因、支持証拠、反証した仮説、修正候補、再発防止、残余不確実性を報告する。

## 安全境界

- 診断依頼では原因特定までに留め、修正は明示依頼がある場合だけ実装する。
- 本番データ削除、広範な権限変更、サービス停止など高リスク試験を避ける。
- 状態を変える前に観測とバックアップを行い、元へ戻せる方法を確保する。
- エラーが消えただけで根本原因解決とせず、再現条件で再確認する。
