# CLAUDE.md

This file guides AI assistants (Claude Code) working in this repository.

## Project overview

**NurseTube（ナースチューブ）** is a static, dependency-free web app: a
"study YouTube" for nurses and nursing students. The mascot **ずんだもん**
explains nursing topics (anatomy/physiology, pharmacology, nursing skills,
diseases, national-exam prep, etc.) in a YouTube-style UI.

Each "program" (番組) is a learning video. When a real YouTube `videoId` is
set, it embeds the actual video; otherwise the app auto-plays a slideshow
(slides + narration) generated from a script, narrated either by the
device's speech synthesis (Web Speech API) or by pre-rendered VOICEVOX
ずんだもん audio.

The entire UI and all content are in **Japanese**, and program/script copy
uses ずんだもん's signature 「〜なのだ／〜のだ」 speech style. Preserve this
tone and language when editing content.

## How to run

No build step, no dependencies. The site root `index.html` is the
**VentSim ventilator monitor** (a standalone single-file app). The NurseTube
app lives at `nurse.html` — open it directly, or serve the folder
(recommended so search/theme persistence work reliably):

```bash
python3 -m http.server 8000   # ventilator: http://localhost:8000/  ·  NurseTube: http://localhost:8000/nurse.html
```

The Node scripts in `tools/` require Node.js (developed against Node 22) and
have **no npm dependencies** — they use only the `node:` built-ins.

## Architecture

Plain **HTML + CSS + vanilla JavaScript**. No framework, no bundler, no
package.json. The NurseTube scripts are loaded as plain globals via
`<script>` tags in this order (see `nurse.html`):

```
data.js  → scenes.js → audio/manifest.js → app.js
```

Each file exposes globals (not modules):

- `data.js` — `CATEGORIES`, `PROGRAMS`, `EXAM_DATE`, `PRESENTER`
- `scenes.js` — `SCENES` (script object keyed by program id)
- `audio/manifest.js` — `AUDIO_FILES` (auto-generated; empty by default)
- `app.js` — the whole app, wrapped in an IIFE (`"use strict"`)

### Routing

Hash-based router in `app.js` (`router()` + `hashchange`):

- `#/` — home (all programs)
- `#/category/<カテゴリ>` — filter by category
- `#/search/<キーワード>` — search title/channel/category/description/tags
- `#/watch/<番組ID>` — watch page (YouTube embed or slideshow player)

### The slideshow player

`createLesson(programId, scenes)` in `app.js` drives auto-play. Playback
priority per scene:

1. Real audio file from `AUDIO_FILES["<id>-<sceneNo>"]` (e.g. VOICEVOX), else
2. Web Speech API narration (`speechSynthesis`, ja-JP), else
3. Silent timed slide advance.

A `token` counter guards against stale timers/utterances when the user
navigates or toggles. Always call `activeLesson.destroy()` on route change
(the router already does this).

## Common tasks

### Add or edit a program

1. Add an entry to `PROGRAMS` in `data.js`. Required fields:
   `id` (unique), `title`, `category` (must match a `CATEGORIES` key),
   `channel` (usually `PRESENTER`), `durationSec`, `views`, `published`
   (`YYYY-MM-DD`), `videoId`, `description`, `tags`.
2. Set `videoId` to a YouTube id to embed the real video, or leave it `""`
   to use the slideshow / search-link fallback.
3. For a slideshow, add `SCENES["<id>"] = [...]` in `scenes.js`. Each scene:
   `{ heading, points: [...], narration }`. The `narration` is read aloud
   and shown as caption.

### Add or change a category

Edit `CATEGORIES` in `data.js`. `key` must match `PROGRAMS[].category`;
`color` drives the thumbnail gradient, `icon` is an emoji, `label` is shown.

### Generate real ずんだもん voice (VOICEVOX)

```bash
node tools/build-voicevox.mjs   # rebuild voicevox/narration.txt + manifests
# → render narration.txt in VOICEVOX (speaker: ずんだもん ノーマル),
#   put exported wavs in voicevox/export/  (gitignored)
node tools/link-audio.mjs       # copy into audio/ and regenerate audio/manifest.js
```

Scenes are numbered program-order then scene-order; the positional order in
`narration.txt`/`manifest.json` must match VOICEVOX's batch export order.
Re-run `build-voicevox.mjs` whenever `data.js`/`scenes.js` change.
⚠ Using VOICEVOX ずんだもん audio requires the credit「VOICEVOX:ずんだもん」.

## The lab assessment apps (`labs*.html`)

A second standalone app family, separate from NurseTube. Target user is a
**clinical nurse at the bedside** (not a student), so the copy is clinical
Japanese — **not** ずんだもん tone. Wards assumed: general, ICU, and
neurosurgery/neurology, plus rheumatology.

Loaded as plain globals in this order:

```
labs-core.js → labs-<domain>.js … → labs-integrate.js → labs-ui.js
```

Each page then calls `LabsUI.mount({ domains: [...], integrate: true, ... })`.

### Adding an analyte

Add an entry to the domain file's `analytes` array:
`{ key, label, unit, group, ref, panic?, decimals, placeholder, note?, facility? }`.
`ref` is `[lo, hi]` or `{ m: [...], f: [...] }` for sex-specific ranges.
Set `facility: true` for anything not in the JCCLS common reference intervals —
the UI then shows a 「施設依存」 badge. `group` must be listed in the domain's
`groups` array. For qualitative items use `type: "qual"`, or `type: "select"`
with an `options` array and an optional `positiveWhen(value)` predicate.

### Adding a judgment

1. Set a flag in the domain's `findings(V, D, ctx)`.
2. Add a `patterns` entry: `{ id, name, level: 'red'|'amber'|'info',
   when(F, V, D, ctx), basis: [...], note, actions: [...] }`.
   `V` is the **flat value map across all loaded domains**, so a pattern may
   read another domain's value directly (it simply never fires when that
   domain is absent). Add `dedupeKey` when two domains express the same
   finding (e.g. severe thrombocytopenia in both `cbc` and `coag`).
3. For a judgment that genuinely needs several domains, add it to
   `syndromes` in `labs-integrate.js` instead — those carry a `story` field
   explaining the pathophysiology.

### The internal-medicine diagnostic app (`dx.html`)

Target user is an **internist**, not a nurse — clinical register, differential
reasoning, and a citation on every judgement. It reuses the whole `labs-*`
engine and adds four things on top.

Load order (globals, no modules):

```
labs-core.js → labs-<domain>.js … → dx-refs.js → dx-abg.js → dx-scores.js
→ dx-core.js → labs-integrate.js → labs-ui.js → dx-ui.js
```

### The four additions

- **`dx-abg.js`** — a blood-gas domain that performs the systematic reading:
  ① pH ② primary disorder ③ adequacy of compensation (Winter's formula; acute
  vs chronic coefficients for respiratory disorders) ④ anion gap with albumin
  correction ⑤ delta-delta ratio ⑥ oxygenation (A-aDO₂, P/F). `derive()` puts
  the whole structured analysis on `D.abg`, and `dx-ui.js` renders its `steps`.
- **`dx-scores.js`** — scores come in two shapes. `direct(V, ctx)` computes
  straight from entered values (MELD-Na, CKD, ISTH DIC). `items` + `compute`
  takes clinical answers, and `autofill(V, ctx)` pre-fills what the labs and
  vitals already say. Returning `null` from `direct` means "not enough data".
- **`dx-core.js`** — the differential engine. Each entry has `trigger` flags
  (with optional `minTrigger` and `requireMed`), weighted `supports` and
  `opposes`, `next` steps, `refs` and a `pearl`. Output is a **fit percentage,
  never a probability** — keep that wording.
- **`dx-refs.js`** — every score, criterion and formula carries a `refs` array
  of IDs resolved here. Add the source before adding the judgement.

### Extending the UI

`labs-ui.js` exposes `LabsUI.addInputPanel(fn)`, `addSection(fn)` and
`addBinder(fn)`. `dx-ui.js` uses them so no page needs its own renderer. A
section receives `{result, input, state}` and returns an HTML string; a thrown
error in one section is swallowed so it cannot break the page.

### Rules for this app

- Never present output as a diagnosis or a probability. 「合致度」 and
  「〜を疑う」 only. The disclaimer footer and modal stay on every page.
- A new judgement without a citation is incomplete — add it to `dx-refs.js`.
- Guard against over-firing: a differential that triggers on one non-specific
  flag will fire on every patient. Use `minTrigger`, `requireMed`, or a more
  specific flag. Verify with the case presets before committing.
- Verify by opening `dx.html`, running the 症例プリセット, and reading the
  acid-base steps and differential ranking. That is this app's regression test.

### The verification checklist (`verify.html`)

The clinical content has to be checked by a clinician against their own
references. `tools/build-verify-checklist.mjs` walks every registry
(analytes, panic values, formulas, scores, differentials, patterns,
syndromes) and regenerates `verify-data.js`, so the checklist cannot drift
from the implementation.

```bash
node tools/build-verify-checklist.mjs   # re-run after changing any judgement
```

`verify.html` renders it with per-item 一致/要修正/違う, free-text notes, a ★
filter for the judgements that drive clinical action, localStorage progress,
a print layout, and an export that emits only the mismatches as pasteable
text (current implementation value next to what the reference says).

**Re-run the generator whenever you add or change an analyte, threshold,
score, differential or pattern** — a stale checklist is worse than none.
Never hand-edit `verify-data.js`.

Marking an item updates that card and the progress bar in place rather than
re-rendering: with 337 items a full re-render collapses the sections and
loses the reader's place.

## Conventions specific to these apps

- Reference ranges default to **JCCLS common reference intervals** (adults).
- Units are conventional Japanese clinical units (Cr/Ca/BUN in mg/dL,
  platelets in ×10⁴/µL).
- Wording avoids assertion: 「〜を疑う／〜の可能性／確認すべきは」, never a
  diagnosis. Every page carries the disclaimer footer and first-visit modal.
- No patient name/ID fields — the apps deliberately hold no personal data.
- Verify changes by opening `labs.html`, running the **症例プリセット**
  buttons, and checking the judgments. That is this project's regression test.

## Conventions

- **Language & tone:** Japanese throughout; ずんだもん 「〜なのだ」 style for
  all user-facing and content copy. Match the existing voice.
- **No dependencies / no build:** keep it vanilla. Don't introduce npm
  packages, frameworks, or a bundler without explicit need. Use globals, not
  ES modules, in the browser code (`tools/*.mjs` do use `node:` ESM imports).
- **Security:** user/content text is escaped with `escapeHtml()` before being
  inserted into `innerHTML`. Keep using it for any dynamic string in markup.
- **State:** theme is persisted in `localStorage` (`nursetube-theme`).
- **No tests / no CI / no linter** are configured. Verify changes by opening
  the app in a browser and exercising the affected route.
