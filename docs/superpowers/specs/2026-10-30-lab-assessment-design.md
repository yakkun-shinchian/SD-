# 血液検査アセスメント支援アプリ 設計書

作成日: 2026-10-30
対象リポジトリ: NurseTube（静的・依存ゼロ・ビルドなし）

## 1. 目的と背景

臨床看護師がベッドサイドで血液検査結果を見たとき、「今この患者に何が起きているのか」
を構造的に読み解くための判断支援ツール。

解決したい課題は **アンカリング・バイアス** である。検査値の異常を1つ見つけると
思考がそこで止まり、同一画面上の他の異常との組み合わせを見落とす。
本ツールは「単独項目の判定」と「組み合わせ（症候群）の判定」を構造的に分離し、
横断視点を強制的に提示することでこれを防ぐ。

## 2. スコープ

### 2.1 作るもの

| アプリ | ファイル | 内容 |
|---|---|---|
| 血算 | `labs-cbc.html` | WBC/RBC/Hb/Ht/Plt/赤血球指数/白血球分画 |
| 生化学 | `labs-chem.html` | 肝・腎・電解質・代謝・心筋・膵・炎症・神経系追加項目 |
| 凝固 | `labs-coag.html` | PT/APTT/Fib/FDP/D-dimer/AT-III/TAT・急性期DIC |
| 自己抗体 | `labs-autoab.html` | 膠原病＋臓器特異的＋神経免疫 |
| 統括 | `labs.html` | 全ドメイン統合・緊急度トリアージ・横断症候群 |

### 2.2 作らないもの（YAGNI）

- サーバ・DB・認証（静的サイトのまま、すべてブラウザ内で完結）
- 患者個人情報の永続保存（localStorage は入力の一時下書きのみ、明示クリア可）
- 検査システム連携・CSV取込
- 小児基準値（成人のみ。小児は基準値体系が別物のため別プロジェクト）

## 3. 前提条件

- **基準値**: 日本臨床検査標準協議会（JCCLS）共用基準範囲を既定とする。
  JCCLS に収載のない項目（凝固・腫瘍マーカー・自己抗体など）は
  一般的な施設値を既定とし、UI上に「施設依存」と明示する。
- **単位系**: 従来単位（Cr・Ca・BUN は mg/dL、Hb は g/dL、電解質は mmol/L）。
- **想定病棟**: 一般病棟・ICU・脳神経外科／神経内科病棟。膠原病領域も含む。
- **対象患者**: 成人。

## 4. アーキテクチャ

### 4.1 方式: パターン認識エンジン型

各ドメインが「正規化した所見フラグ」を生成し、統括層がフラグの組み合わせを
症候群パターンに照合する。判定根拠（どのフラグが効いたか）を常に提示できる
説明可能性を最優先とする。

ベイズ／尤度比方式は説明可能性が落ちるため採用しない。

### 4.2 ファイル構成

```
labs-core.js       共通基盤：レジストリ・基準値解決・フラグ判定・評価エンジン・派生値計算
labs-cbc.js        血算ドメイン定義
labs-chem.js       生化学ドメイン定義
labs-coag.js       凝固ドメイン定義
labs-autoab.js     自己抗体ドメイン定義
labs-integrate.js  統括層：横断症候群・緊急度トリアージ・看護アクション
labs-ui.js         共通UI：フォーム生成・結果描画・プリセット・保存・印刷
labs.css           共通スタイル（VentSim 準拠のダーク臨床テーマ）
labs-*.html        各アプリのページ（スクリプト読込と mount 呼び出しのみ）
```

既存ファイル（`index.html` / `nurse.html` / `app.js` ほか）は変更しない。
`<script>` によるグローバル公開（CLAUDE.md の方針どおり、ESモジュールは使わない）。

### 4.3 ドメイン定義のインターフェース

```js
LabsCore.register({
  id: 'cbc',
  title: '血算',
  groups: [...],               // 入力フォームのグループ順
  analytes: [ {
    key, label, unit, group,
    ref: [lo,hi] | {m:[lo,hi], f:[lo,hi]},
    panic: {low, high},        // 任意
    decimals, placeholder, note, facility: true|false
  } ],
  derive(V, C) -> D,           // 派生値（MCV・ANC・eGFR・補正Ca など）
  findings(V, D, C) -> {flag: true},
  patterns: [ {
    id, name, level: 'red'|'amber'|'info',
    when(F, V, D, C) -> bool,
    basis: [...], note, actions: [...]
  } ],
  presets: [ {name, note, values, context} ]
});
```

- `V` 入力値（数値／定性値）
- `D` 派生値
- `C` 患者背景（年齢・性別・妊娠・バイタル・主訴・既往・内服）
- `F` 所見フラグ

### 4.4 データフロー

```
入力 {背景, バイタル, 主訴, 既往, 内服, 検査値}
  ↓  LabsCore.evaluate(domainIds, input)
各ドメイン → {items[], derived, findings, patterns[]}
  ↓  LabsIntegrate.assess(input, results)
統括 → {triage, headline, syndromes[], organMap, actions[], watch[], callDoctor[]}
```

## 5. 判定ロジックの要点

### 5.1 緊急度トリアージ

最上段に赤／黄／緑を表示する。赤（即 Dr. コール）の既定条件：

K > 6.5 または < 2.5 ／ Na < 120 または > 160 ／ 血糖 < 50 ／
Plt < 2万 ／ Hb < 6 ／ 好中球絶対数 < 500 かつ発熱 ／ PT-INR > 5 ／
補正Ca > 12 または < 7 ／ トロポニン上昇 ／ 乳酸 ≥ 4 mmol/L ／
急性期DIC スコア該当 ／ アンモニア高値 + 意識障害

パニック値の閾値は施設規定が優先される旨を UI に明示する。

### 5.2 横断症候群パターン（統括層）

- DIC: 血小板減少 + FDP/D-dimer上昇 + フィブリノゲン低下 + PT延長
- 汎血球減少: 骨髄抑制／MDS／脾機能亢進／血球貪食症候群
- 肝不全・肝硬変: 肝逸脱酵素 + Alb低下 + PT延長 + 血小板減少 + NH3上昇
- 消化管出血疑い: BUN/Cr比 > 20 + Hb低下
- 敗血症: 炎症マーカー + qSOFA + 乳酸 + 臓器障害
- 溶血: LD上昇 + 間接ビリルビン上昇 + Hp低下 + 網赤血球増加
- 腫瘍崩壊症候群: K・P・UA上昇 + Ca低下 + Cr上昇
- 横紋筋融解: CK著明高値 + Cr上昇 + K上昇
- 膠原病の臓器障害: 自己抗体陽性 + 多臓器所見

### 5.3 脳神経領域の重点ロジック

- **低Na血症の三分岐**: SIADH（尿浸透圧高・尿中Na高・体液正常〜過剰）／
  CSWS（同所見だが体液減少・多尿が先行）／尿崩症（高Na・尿浸透圧低）。
  血清浸透圧・尿浸透圧・尿中Na を任意入力項目として用意し、
  入力があれば鑑別フローを提示する。
- **抗てんかん薬**: バルプロ酸 → 高アンモニア血症・血小板減少・肝障害、
  カルバマゼピン → 低Na血症・汎血球減少、フェニトイン → 肝酵素誘導。
- **浸透圧利尿薬**（マンニトール／グリセオール）: Na・浸透圧・腎機能への影響。
- **神経免疫抗体**: 抗AQP4・抗MOG（NMOSD/MOGAD）、抗ガングリオシド GM1・GQ1b
  （GBS／Fisher症候群）、抗NMDA受容体・抗LGI1・抗CASPR2（自己免疫性脳炎）、
  抗AChR・抗MuSK（重症筋無力症）、傍腫瘍性 抗Hu・抗Yo・抗Ri。

### 5.4 患者背景を解釈に反映する

背景入力は飾りではなく、解釈そのものを書き換える。

- 年齢・性別 → 基準値の切替（Hb・Cr・UA・γGT・CK ほか）
- 妊娠 → D-dimer・フィブリノゲン・ALP の生理的上昇を補正
- 内服薬 → ワルファリン(INR) ／ ヘパリン(APTT・HIT警戒) ／ DOAC ／
  スタチン(CK) ／ 利尿薬(K・Na) ／ ステロイド(白血球偽上昇・血糖) ／
  化学療法(発熱性好中球減少症) ／ PPI(Mg・B12) ／
  抗てんかん薬(NH3・Na・血球) ／ 浸透圧利尿薬(Na・浸透圧)
- 既往 → 肝硬変・CKD・血液疾患・膠原病があれば解釈の基準線を移動

## 6. 安全設計

臨床判断支援を名乗る以上、以下を必須とする。

1. 全ページのフッターに常時表示、かつ初回アクセス時にモーダルで同意を求める:
   「本ツールは教育・補助目的です。診断・治療の決定は医師が行います。
    パニック値の基準は各施設の規定に従ってください。」
2. 出力文言は断定を避け「〜を疑う／〜の可能性／確認すべきは」という
   鑑別提示の語法に統一する。
3. 患者氏名・ID の入力欄は設けない（個人情報を扱わない設計）。
4. localStorage に保存するのは入力下書きのみとし、ワンタップで消去できる。
5. 動的文字列は必ずエスケープしてから `innerHTML` に渡す（既存方針を踏襲）。

## 7. 検証方法

テストフレームワークは導入しない（リポジトリ方針）。代わりに
**症例プリセット**を各アプリに内蔵し、ワンタップで典型症例を流し込んで
期待どおり判定されるかを目視確認する。これが実質の回帰テストであり、
同時に学習ツールとしても機能する。

収載する症例（最低限）:
鉄欠乏性貧血／巨赤芽球性貧血／溶血性貧血／発熱性好中球減少症／
急性白血病示唆／ITP／DIC／ワルファリン過量／血友病パターン（APTT単独延長）／
敗血症／肝硬変／急性肝炎／CKD／脱水／消化管出血／糖尿病性ケトアシドーシス／
横紋筋融解／腫瘍崩壊症候群／SIADH／中枢性塩類喪失症候群／尿崩症／
SLE／関節リウマチ／全身性強皮症／シェーグレン／ANCA関連血管炎／
重症筋無力症／視神経脊髄炎／ギラン・バレー症候群／橋本病／バセドウ病／
原発性胆汁性胆管炎

ブラウザ確認手順:
```bash
python3 -m http.server 8000
# http://localhost:8000/labs.html
```

## 8. 既知の限界

- 基準値は JCCLS 共用基準範囲であり、施設の測定系により差異がある。
- 凝固・自己抗体の基準値は施設依存であり、既定値は目安にすぎない。
- 本ツールは鑑別の候補を提示するものであり、診断を行わない。
- 検査値のみでは判断できない所見（画像・身体所見・経過）は扱わない。
