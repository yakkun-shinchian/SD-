# RadioDeck — 放射線科 読影アトラス 設計仕様書

- 日付: 2026-10-31
- ブランチ: `feature/radiology-reader`
- 状態: v1 実装済み

---

## 1. 目的と背景

### 作るもの

頭部CT/MRI・胸部X線/CT・腹部CT/MRI の所見について、**「これは何か」と「なぜそう見えるのか」の両方に答える**、公開可能な学習用Webアプリ。

### なぜ作るのか

所見名を列挙する教材は多いが、**その所見がなぜそう見えるのかを物理と病態生理から説明する教材はほとんどない**。機序が腑に落ちると、学習者は見たことのない所見に対しても推論できるようになる。そこを本アプリの中核に据える。

### 対象ユーザー

看護学生・新人看護師・国家試験受験者、および制作者自身（やっくん）の学習。一般公開する教育アプリとして設計する。

### 成功の定義（受け入れ基準）

ユーザーの原語による要求をそのまま基準とする。

1. 画像を見ながら、部位と見えた形から所見名にたどり着ける
2. 「ケーリーBラインはどうやってできるの、どうしてできるの？」に、機序まで腑に落ちる答えが返る

## 2. 決定事項と、その理由

| 論点 | 決定 | 理由 |
|---|---|---|
| 用途 | 一般公開の教育アプリ | ユーザーが選択。患者画像を扱わない前提を明示する |
| 画像素材 | 自作SVG模式図（＋将来のAI生成図） | 他者の放射線画像は著作権上、公開アプリに転載できない。模式図は初学者にとってむしろ可読性が高い |
| AI読影 | 本体はAI不要で全機能動作。その上に自前APIキー（BYOK）方式のAI読影タブ | サーバー不要・コストゼロ・静的サイトのまま。鍵を持たない訪問者も本体を完全に使える |
| コード構成 | 独立アプリ `radiology.html` ＋ 専用JS群。NurseTubeからはリンクで接続 | 読影UIは暗背景・辞書的な引き方・チャットを要し、YouTube風カードUIと噛み合わない。NurseTubeを一切壊さず、両者が独立して育つ |
| 口調 | 「やさしく」はずんだもん調（〜なのだ）、「しっかり」は専門水準の記述 | リポジトリの口調規約を守りつつ、レベル切替に意味を持たせる |

### 却下した案

- **NurseTubeへの統合**: `app.js` が肥大し、辞典・ウィザード・チャットが「動画カード一覧」のメタファーに収まらない。
- **バックエンドを立ててAIを全員に開放**: 制作者が全訪問者のAPI料金を負担することになり、GitHub Pages から離れ、「依存なし・ビルドなし」規約が崩れる。
- **AIなしで逆引きと教育だけのv1**: ユーザーが最もやりたい「写真を撮って聞く」が後回しになる。

## 3. アーキテクチャ

プレーンHTML + CSS + バニラJS。ビルドなし、npm依存なし。スクリプトはグローバルとして順に読み込む。

```
radiology-atlas.js  →  radiology-figures.js  →  radiology-signs.js  →  radiology-app.js
```

| ファイル | 役割 | 公開するグローバル |
|---|---|---|
| `radiology.html` | 骨格（ヘッダー・免責・タブ・main） | — |
| `radiology.css` | ダーク既定のスタイル＋SVG図の配色 | — |
| `radiology-atlas.js` | 領域・モダリティ・逆引き軸・読影手順・CT値表 | `RAD_REGIONS` `RAD_AXES` `RAD_PROTOCOLS` `RAD_HU` |
| `radiology-figures.js` | 自作SVG模式図ライブラリ | `RAD_FIGURES` |
| `radiology-signs.js` | 所見辞典データ（★ PDFの知見はここへ） | `RAD_SIGNS` |
| `radiology-app.js` | ルーティング・逆引き・描画・AI連携（IIFE） | — |

### ルーティング

`radiology-app.js` のハッシュルーター（`router()` + `hashchange`）。

| ルート | 画面 |
|---|---|
| `#/` | ホーム（領域選択・緊急所見・CT値表） |
| `#/navigate` | 逆引き：領域を選ぶ |
| `#/navigate/<region>` | 逆引き：軸を選んで絞り込む |
| `#/dict` / `#/dict/<region>` | 所見辞典の一覧 |
| `#/sign/<id>` | 所見の詳細 |
| `#/protocol` / `#/protocol/<key>` | 系統的読影手順 |
| `#/assist` | AI読影（BYOK） |
| `#/search/<q>` | 検索結果 |

### 状態の保存（localStorage）

| キー | 内容 |
|---|---|
| `radiodeck-theme` | `light` / `dark` |
| `radiodeck-level` | `easy` / `deep` |
| `radiodeck-checks` | 読影手順のチェック状態 |
| `radiodeck-apikey` | APIキー（ユーザーが「保存する」を選んだ場合のみ） |
| `radiodeck-model` | 選択中のモデルID |

## 4. 3つの柱

### ① 所見辞典（RAD_SIGNS）

本アプリの中核。1件のスキーマ:

```js
{
  id, name, en, reading,          // reading はひらがな検索用
  region: "head" | "chest" | "abdomen",
  modality: [...],
  patterns: [...],                // 逆引きのtag。RAD_AXES と対応させる
  urgency: "emergency" | "urgent" | "routine",
  oneLine,                        // 一行で言うと
  easy,                           // やさしく（ずんだもん調）
  deep,                           // しっかり（専門水準）
  mechanism: [{ step, text }],    // ★ なぜそう見えるのか（段階説明）
  lookFor: [...], ddx: [{name, hint}], pearls: [...], pitfalls: [...],
  figure,                         // RAD_FIGURES のキー
  refs: [{label, url}],           // 省略可。Radiopaedia検索リンクは自動生成
}
```

`mechanism` が本アプリの価値の源泉である。他の項目は省略しても成立するが、ここだけは手を抜かない。

v1 収録数: **32件**（胸部12・頭部9・腹部11）

### ② 逆引きナビ（RAD_AXES）

領域ごとに質問軸を持ち、選んだ `tag` と各所見の `patterns` の一致数でスコアリングし、降順に提示する。AIを一切使わず、画像を見ながら自分の目で絞り込ませる設計。選択ゼロのときは緊急度順に全件を出す。

### ③ 系統的読影手順（RAD_PROTOCOLS）

「見落としは能力ではなく手順の問題」という立場に基づくチェックリスト。胸部X線のABCDE+F、頭部CTの Blood Can Be Very Bad、腹部CTの巡回ルートを収録。各ステップに「なぜ見るのか」を併記する。チェック状態は localStorage に保存。

### ④（補助）AI読影タブ

ユーザー自身のAnthropic APIキーで、ブラウザから直接 `api.anthropic.com` を呼ぶ。システムプロンプトで放射線科医の教育者役を与え、**断定を禁止**し、**患者画像と判断した場合は解析を拒否して注意喚起する**よう指示する。回答文に登場した所見名は辞典エントリへのリンクとして提示し、AIの出力を必ず検証可能な教材に接続する。

## 5. 安全性と権利

本アプリが公開教育アプリであることから、以下を設計に織り込む。

- 画面上部に常設の免責バナー。「くわしく」で全文を展開。
- すべてのSVG図のコンテナに「模式図（実際の患者画像ではありません）」を**CSSで自動付与**する。データ側の記入漏れで消えない構造にする。
- AI読影タブには、患者画像をアップロードしないよう赤枠で明示。システムプロンプト側でも二重に防御する。
- APIキーはブラウザ内のみ。保存するかどうかをユーザーが選べる。
- 実例が見たいユーザーには、画像を転載せず **Radiopaedia の検索リンク**へ送り出す。

### 参考資料の扱い（重要）

制作にあたり商業出版物（例: 『見逃し、誤りを防ぐ！ 肝・胆・膵癌 画像診断アトラス』羊土社, 2010）を参照する場合、

- ✅ 知識として読み、**自分の言葉で書き直す**（事実・アイデアに著作権はない）
- ✅ 扱うべき疾患の網羅性のチェックリストとして使う
- ✅ 参考文献として書誌を明記する
- ❌ 本文表現をそのまま／ほぼそのまま転載する
- ❌ 掲載画像を転載する
- ❌ 目次構成をそのまま複製する

裏取りは一次情報（診療ガイドライン、癌取扱い規約、PubMed文献）で行う。

## 6. 検証方法

本リポジトリにはテスト・CI・リンタがない。検証はブラウザで実際に動かして行う。

```bash
python3 -m http.server 8000   # → http://localhost:8000/radiology.html
```

v1 では Playwright で全ルートを走査し、以下を確認済み。

- 全ルートが描画され、JSエラー・コンソールエラーがゼロ
- 逆引きで「線状・網状」＋「下肺野」を選ぶと、ケーリーBラインが第1候補になる
- 「やさしく／しっかり」の切替が詳細画面に反映される
- 読影手順のチェックがリロード後も保持される
- ライト／ダーク両テーマが破綻しない
- 幅390pxで横スクロールが発生しない
- `RAD_FIGURES` の全30図が例外なく描画される

## 7. 今後の拡張（v1には含めない）

1. **所見の拡充** — 投入予定のPDFから、特に胸部X線と頭部CTの所見を追加する。腹部は肝胆膵の腫瘍性病変を深掘りできる資料が既にある。
2. **AI生成図の導入** — ChatGPTの画像生成で作った**ラベル付き模式図**を `images/` に置き、`figure` から参照できるようにする。「本物そっくりの偽レントゲン」は作らない（存在しない所見を学習させる害があるため）。
3. **症例クイズモード** — 図を見せて所見名を当て、機序の解説へ送る。
4. **国試過去問とのひもづけ** — 所見から関連する国試問題へ。
5. **NurseTubeとの相互リンク強化** — 関連する番組へのリンクを所見詳細に置く。

### 拡張時の原則

- `radiology-signs.js` にエントリを足すだけで辞典・逆引き・検索すべてに反映される。`patterns` を `RAD_AXES` の `tag` と一致させることだけ忘れないこと。
- 図がまだない所見は `figure: "placeholder"` でよい。文章だけでも公開する価値がある。
