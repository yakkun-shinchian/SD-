# CoeFont 音声量産パイプライン 設計書

作成日: 2026-11-02 / 対象ブランチ: `feature/coefont-batch`

## 1. 何を作るのか

`scenes.js` の全ナレーション（118本）を、**CoeFont（声フォント）のお気に入りの声**で
音声ファイル化し、`audio/` に整列させて `audio/manifest.js` を生成する道具を作ります。

既存の VOICEVOX パイプラインと**同じ契約**に乗ります。つまり NurseTube 本体のコードは
1行も変わりません。アプリは `audio/manifest.js` の `AUDIO_FILES` だけを見ており、
その音声を誰が作ったかを知りません。CoeFont は「もう一つの声の供給元」として並びます。

```
scenes.js ──(build-voicevox.mjs)──> voicevox/manifest.json ─┬─> VOICEVOX 経路（既存）
                                    （通し番号・キー・本文）   └─> CoeFont 経路（新規）
                                                                      ↓
                                                        audio/<番組ID-シーン番号>.<ext>
                                                        audio/manifest.js
```

`voicevox/manifest.json` を共通の入力とするのが要点です。「どのシーンが何番で、
本文は何か」という対応表は既にそこにあります。作り直しません。

## 2. なぜブラウザ自動化なのか（そして、その弱点）

CoeFont には公式 REST API（`POST https://api.coefont.cloud/v2/text2speech`、
HMAC-SHA256 署名）がありますが、**有料プラン限定**の可能性があり、
利用者のアカウントで使えるかが未確認です。そのため当面は Web 編集画面を
機械が操作する方式を採ります。

ブラウザ自動化の弱点は率直に認めておきます。

- **サイトの模様替えで壊れる。** これは回避できません。緩和策は §4-1。
- **Google ログインは自動化しない。** パスワードを扱わず、2段階認証も越えられず、
  Google は自動操作ブラウザを検知します。**初回のみ人間が手でログインし、
  以降はブラウザプロファイルを再利用**します（§4-2）。
- **API に乗り換えられる余地を残す。** 入口（manifest 読み込み）と
  出口（`audio/` への整列）を共通化しておき、中間の「音声を得る手段」だけを
  差し替えられる構造にします。

## 3. 構成

```
tools/coefont/
  coefont-login.mjs   ① 初回のみ。ブラウザを開き、利用者が手でGoogleログイン
                         → プロファイルを .profile/ に保存（gitignore）
  coefont-probe.mjs   ② 画面を「採寸」し、ui-map-NN.json と画面写真を出力
  selectors.js        ③ 画面の知識を閉じ込める唯一のファイル
  coefont-batch.mjs   ④ 本番。台本を流し込み、音声を書き出して audio/ へ整列
  README.md           手順書（日本語）
  .profile/           ブラウザプロファイル（gitignore・認証情報を含む）
  export/             ダウンロードした音声の一時置き場（gitignore）
  progress.json       進捗記録（再実行で未完了分のみ処理）
```

実装順序は ① → ② → **採寸** → ③ → ④ です。②で実物を測るまで③は書けません。
推測で書いた選択子は初回で外れるため、採寸を先に置きます。

## 4. 設計上の判断

### 4-1. 画面の知識を1ファイルに閉じ込める（`selectors.js`）

CSS選択子・ボタンの文言・待機条件を、すべて `selectors.js` に集約します。
CoeFont が改装したとき、直すのはこの1枚だけで、他のファイルは無傷です。
「変わるもの」と「変わらないもの」を分離する、という基本に従います。

### 4-2. 認証情報は保持しない

パスワードもトークンもコードにも環境変数にも書きません。永続化するのは
Chromium のユーザープロファイル（`tools/coefont/.profile/`）だけで、これは
`.gitignore` に入れ、リポジトリには一切入りません。初回のログインは
利用者が自分の画面で自分の手で行います。

### 4-3. 再実行可能にする（`progress.json`）

118本を1本ごとに記録します。90本目で失敗しても、再実行は残り28本だけを処理します。
有料サービスで全量やり直しは避けます。

### 4-4. 声は名前で検索して選ぶ

CoeFont の声は数百あり、UUID を人間が管理するのは現実的ではありません。
`--voice "<名前の一部>"` で一覧を検索し、候補が複数あれば**一覧を提示して止まる**
（勝手に1つ選ばない）方針とします。

### 4-5. 出力は既存の契約に合わせる

`audio/<番組ID-シーン番号>.<拡張子>` に置き、`audio/manifest.js` を再生成します。
既存の `tools/link-audio.mjs` と同じ出力形式です。アプリ側は無改修。

## 5. 検証方法

本リポジトリの回帰テストは「ブラウザで画面を開いて確かめる」ことです。それに倣います。

1. `node tools/coefont/coefont-probe.mjs` で採寸結果と画面写真を確認
2. `coefont-batch.mjs --limit 3` で3本だけ生成し、`audio/` に正しい名前で
   並ぶか、`audio/manifest.js` が妥当かを確認
3. `nurse.html` を開いて該当番組を再生し、**実際に声が鳴るか**を耳で確認
4. その後に全118本

`--limit` を付けずに初回から全量を走らせることはしません。

## 6. やらないこと（意図的な範囲外）

- **Google ログインの完全自動化** — §2 の理由により行いません
- **`PRESENTER` の変更** — チャンネル名は出演者に関する判断で、本件の範囲外
- **VOICEVOX パイプラインの削除** — 動作する機能として維持します
- **CoeFont 側のプロジェクト管理機能** — 音声を得ることが目的で、
  編集画面の全機能を操作する道具は作りません

## 7. 未解決事項

- **CoeFont の規約確認。** 生成音声の利用範囲とクレジット表記の要否を、
  実際のプラン規約で確認する必要があります。VOICEVOX の
  「VOICEVOX:ずんだもん」表記義務とは条件が異なります。
- **API の可否。** 利用者のプランで API キーが発行できるなら、
  ブラウザ自動化より確実です。§2 の構造により、後からでも乗り換えられます。
- **この環境のネットワーク制限。** クラウド実行環境からは `coefont.cloud` に
  到達できません。本道具は利用者のパソコン上で実行する前提です。
