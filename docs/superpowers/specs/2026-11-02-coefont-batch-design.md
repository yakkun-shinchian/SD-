# CoeFont 音声量産パイプライン 設計書

作成日: 2026-11-02 / 対象ブランチ: `feature/coefont-batch`

## 1. 何を作るのか

`scenes.js` の全ナレーション（118本）を、**CoeFont（声フォント）のお気に入りの声**で
音声ファイル化し、`audio/` に整列させて `audio/manifest.js` を生成する道具を作ります。

### ⚠ PR #30 との分担（2026-11-02 に判明）

別のセッションが **PR #30**（`feature/coefont-reading-pipeline`）で、同じ CoeFont 案件の
**別の半分**を作っていました。重複ではなく、ちょうど噛み合います。

| 担当 | 範囲 | 成果物 |
| --- | --- | --- |
| **PR #30** | 読み（かな化）と**取り込み** | `tools/build-coefont.mjs`・`tools/import-coefont.mjs`・`coefont/` |
| **本PR #29** | CoeFont の**画面操作**（音声を得る部分） | `tools/coefont/` |

つなぎ目を踏み外さないことが決定的です。**`audio/manifest.js` を書くのは #30 だけ**にします。
二つの道具が同じ対応表を書き換える構造は、競合と取りこぼしの温床です。

```
scenes.js
  ├─(build-voicevox.mjs)─> voicevox/manifest.json ──> VOICEVOX 経路（既存）
  └─(build-coefont.mjs #30)─> coefont/manifest.json
                              coefont/scripts/NNN_<key>.txt   ← 読み（かな）台本
                                        │
                                        ↓  ★ ここが本PRの担当
                              CoeFont の画面を機械が操作して音声化
                              → coefont/export/<key>.<ext>
                              → coefont/import.json を書き出す
                                        │
                                        ↓
                              (import-coefont.mjs #30)
                              ffmpeg で1.3倍速 → audio/<batch>/<key>.wav
                              audio/manifest.js を更新（**#30 の責務**）
```

つまり本PRは、**読み台本を受け取り、音声ファイルと `import.json` を置くところまで**で
手を離します。アプリ本体のコードは、どちらの経路でも1行も変わりません。

## 2. なぜブラウザ自動化なのか（そして、その弱点）

CoeFont には公式 REST API（`POST https://api.coefont.cloud/v2/text2speech`、
HMAC-SHA256 署名）がありますが、**費用を理由に採用しないことを決定しました**
（2026-11-02）。したがって Web 編集画面を機械が操作する方式が**唯一の道**です。

この決定には重い意味があります。退路が無いため、壊れにくさへの投資を
通常より厚くします（§4-1）。

ブラウザ自動化の弱点は率直に認めておきます。

- **サイトの模様替えで壊れる。** これは回避できません。緩和策は §4-1。
- **Google ログインは自動化しない。** パスワードを扱わず、2段階認証も越えられず、
  Google は自動操作ブラウザを検知します。**初回のみ人間が手でログインし、
  以降はブラウザプロファイルを再利用**します（§4-2）。
- **それでも入口と出口は分離しておく。** 入口（manifest 読み込み）と
  出口（`audio/` への整列）を中間の「音声を得る手段」から切り離します。
  API に戻るためではなく、手段が1つしかないときこそ、その1つを
  交換可能な部品として扱うべきだからです。

## 3. 構成

```
tools/coefont/
  coefont-login.mjs   ① 初回のみ。ブラウザを開き、利用者が手でGoogleログイン
                         → プロファイルを .profile/ に保存（gitignore）
  coefont-probe.mjs   ② 画面を「採寸」し、ui-map-NN.json と画面写真を出力
  selectors.js        ③ 画面の知識を閉じ込める唯一のファイル
  coefont-batch.mjs   ④ 本番。台本を流し込み、音声と import.json を書き出す
  coefont-batch.test.mjs  ④の検証（ブラウザ不要の部分を全部）
  README.md           手順書（日本語）
  .profile/           ブラウザプロファイル（gitignore・認証情報を含む）
  export/             ダウンロードした音声の一時置き場（gitignore）
  progress.json       進捗記録（再実行で未完了分のみ処理）
```

実装順序は ① → ② → **採寸** → ③ → ④ です。②で実物を測るまで③は書けません。
推測で書いた選択子は初回で外れるため、採寸を先に置きます。

④ の入出力は PR #30 のつなぎ目に合わせます。

- **入力**：`coefont/manifest.json`（#30 が生成。`key`・`speech_text`・`source_sha256` を持つ）
  と `coefont/scripts/NNN_<key>.txt`。※ `voicevox/manifest.json` は読みません
  （読み（かな）変換済みの本文を使う必要があるため）
- **声**：**検索語とラベルは別物**として扱います（#30 の実物を読んで判明）
  - `--voice`（既定 `後藤`）… CoeFont の画面で声を探す語。一意に絞れないときは
    候補を並べて停止し、勝手には選びません
  - `--voice-label`（既定 `後藤さん`）… `import.json` に書く値。#30 の
    `import-coefont.mjs` はこの文字列と完全一致しないと取り込みを拒否します。
    画面上の名前が違っても、ラベルは #30 の要求に合わせる必要があります
- **出力**：`coefont/export/<key>.<ext>` と `coefont/import.json`
  （`key`・`file`・`input_speed`・`voice`・`source_sha256`・`speech_sha256`）
  - `file` は `export/<key>.<ext>`。#30 は `import.json` のあるフォルダから
    相対解決するため、置き場所は `tools/coefont/export/` ではなく
    **`coefont/export/`** です（#30 の `import-template.json` の実物で確認）
  - `speech_sha256` は読み本文の **改行なし** SHA-256（#30 の実データで検証済み）
- **その先**：`node tools/import-coefont.mjs coefont/import.json` に引き渡す。
  **本PRは `audio/` にも `audio/manifest.js` にも触りません**

## 4. 設計上の判断

### 4-1. 画面の知識を1ファイルに閉じ込め、かつ候補を複数持たせる

CSS選択子・ボタンの文言・待機条件を、すべて `selectors.js` に集約します。
CoeFont が改装したとき、直すのはこの1枚だけで、他のファイルは無傷です。

さらに、**1つの目標に対して当て方を複数（候補の配列）持たせます**。
上から順に試し、最初に見つかったものを使います。

```js
project: {
  newButton: [
    { role: "button", name: /新規|作成|新しい/ },  // ① 役割と文言（最も頑健）
    { text: "新規プロジェクト" },                   // ② 文言そのまま
    { testId: "new-project" },                      // ③ テスト用属性
    { css: "button.new-project" },                  // ④ CSS（最も脆い）
  ],
}
```

文言や役割で当てるのが CSS クラスより模様替えに強いため、頑健な順に並べます。
ボタンの文字が変わっても ③④ が残り、クラス名が変わっても ①② が残ります。
**4つ全部が同時に外れないと壊れない**という形にします。

API という退路を持たないと決めたので、ここは厚くします。

### 4-2. 認証情報は保持しない

パスワードもトークンもコードにも環境変数にも書きません。永続化するのは
Chromium のユーザープロファイル（`tools/coefont/.profile/`）だけで、これは
`.gitignore` に入れ、リポジトリには一切入りません。初回のログインは
利用者が自分の画面で自分の手で行います。

### 4-3. 再実行可能にする（`progress.json`）

118本を1本ごとに記録します。90本目で失敗しても、再実行は残り28本だけを処理します。
有料サービスで全量やり直しは避けます。

### 4-4. 声は名前で検索して選ぶ

CoeFont の声は数百あり、UUID を人間が管理するのは現実的ではありません。
`--voice "<名前の一部>"` で一覧を検索し、候補が複数あれば**一覧を提示して止まる**
（勝手に1つ選ばない）方針とします。

### 4-5. 出力は #30 の取り込み口に合わせる（対応表は書かない）

`audio/manifest.js` を書き換える道具が二つあると、競合と取りこぼしが必ず起きます。
#30 の `import-coefont.mjs` は、ハッシュ照合・キー指定の取り込み・staging と
ロールバック・既存キーの保持まで備えています。これを置き換える理由はありません。

本PRは `coefont/export/` に音声を置き、`coefont/import.json` を書くだけにします。
#30 がそれを受け取って、1.3倍速に揃えて `audio/` に収め、対応表を更新します。

## 5. 検証方法

本リポジトリの回帰テストは「ブラウザで画面を開いて確かめる」ことです。それに倣います。

1. `node tools/coefont/coefont-probe.mjs` で採寸結果と画面写真を確認
2. `coefont-batch.mjs --limit 3` で3本だけ生成し、`audio/` に正しい名前で
   並ぶか、`audio/manifest.js` が妥当かを確認
3. `nurse.html` を開いて該当番組を再生し、**実際に声が鳴るか**を耳で確認
4. その後に全118本

`--limit` を付けずに初回から全量を走らせることはしません。

## 6. やらないこと（意図的な範囲外）

- **Google ログインの完全自動化** — §2 の理由により行いません
- **`PRESENTER` の変更** — チャンネル名は出演者に関する判断で、本件の範囲外
- **VOICEVOX パイプラインの削除** — 動作する機能として維持します
- **CoeFont 側のプロジェクト管理機能** — 音声を得ることが目的で、
  編集画面の全機能を操作する道具は作りません
- **`audio/` と `audio/manifest.js` への書き込み** — PR #30 の
  `tools/import-coefont.mjs` の責務です（§4-5）
- **読み（かな）変換** — PR #30 の `tools/build-coefont.mjs` の責務です
- **1.3倍速化** — PR #30 が ffmpeg で行います

  実際のプラン規約で確認する必要があります。VOICEVOX の
  「VOICEVOX:ずんだもん」表記義務とは条件が異なります。
- ~~**API の可否。**~~ **決定済み（2026-11-02）**：費用を理由に採用しません。

- **この環境のネットワーク制限。** クラウド実行環境からは `coefont.cloud` に
  到達できません。本道具は利用者のパソコン上で実行する前提です。
- **マージ順序。** #30 は #28 を土台にしています（base が
  `feature/plain-japanese-narration`）。したがって **#28 → #30 → #29** の順に
  取り込むのが安全です。本PRは `main` から分岐しているため、#30 がマージされたあとに

- **読み（かな）の人による確認。** #30 は118シーン分のかな台本を自動生成し、
  「人による確認欄は未確認」と明記しています。医学用語の読みは耳で確かめる必要があり、
  これは本PRの範囲外ですが、**音声を量産する前に済ませるべき**項目です。
