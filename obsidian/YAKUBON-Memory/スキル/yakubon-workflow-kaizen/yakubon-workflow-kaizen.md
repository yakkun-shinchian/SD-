# 1本ごとのカイゼン（YAKUBON STUDIO）

動画を1本作るたびに、Claude自身が「ここはまずかった」と思った所を見つけて、次の1本がよくなるように道具を直す。本人に言われる前に気づいて直すのがこのスキルの目的。

## いつ使うか
- 動画を納品した直後（キャプションのあと）に毎回。頼まれなくても。
- 制作の途中で同じ失敗が2回起きたら、その場で。
- 作業を始める前に `C:\YAKUBON_STUDIO\logs\kaizen.md` の直近5件を読み、同じ失敗をくり返さない。

## 1. 振り返る
今回の1本について、次を見る（コマ抜き・数値・作業記録から）。
- 背景が純黒 #000000 か（四隅と上下の端の帯の平均値。RGB 8 を超えた場面）
- 形の崩れ・溶ける・増える・ちらつき・文字の混入
- 色（青のグラデーションが基本、赤はワンアクセントだけ）
- テロップのかぶり（顔・病変・手）、引き出し線とラベルの見やすさ
- 声と映像のずれ、1秒以上の無音
- 時間（ComfyUIの待ち時間、作り直しの回数）、使ったクレジット
- 本人から言われた直し（いちばん大事。言われたことは必ず原因までさかのぼる）

それぞれ「何が起きた／どの場面・どの道具／原因の層」を書く。原因の層は次の5つ。
- A：指示文（プロンプト・ネガティブ）
- B：ワークフローの設定（解像度・フレーム数・steps・cfg・sampler・シード・LoRAの強さ・前後処理）
- C：つなぎのスクリプト（build_*.py、make_iris_v2.py、render_iris.ps1 など）
- D：スキル・CLAUDE.md のルール
- E：道具そのものが合っていない → 新しいワークフローを考える

## 2. 直す
- **A・B・C は本人に聞かずに直してよい。**
- ワークフローのJSONは上書きしない。`pipeline\workflows\<名前>_v<番号>.json` として新しく保存し、元は残す。何をなぜ変えたかは `pipeline\workflows\CHANGELOG.md` に書く。
- 直したら、問題が起きた場面で同じシードのまま1本だけ試す。前よりよくなったときだけ、標準（jobs_ltx.json や run_ltx_*.py が指す版）を新しい版に切り替える。悪くなったら戻す。
- 一度に直す大きな所は1〜3個まで。全部いじると何が効いたか分からなくなる。
- **新しいワークフローを作ってよい**：同じ種類の失敗が2本続いた／今の道具では直らない／もっと安く・速く・きれいにできる見込みがある、とき。例：背景を黒に固定する前後処理つきLTX、CTの上下スクロール専用、ヒーローの回り込み専用、女の子の小さな動き専用。作ったら1場面で試し、よければ標準候補として CHANGELOG に書く。
- 新しいモデル・カスタムノード・LoRAのダウンロードは、名前・入手元・サイズ・ライセンス（商用で使えるか）を伝えて、本人の「いいよ」をもらってから。商用不可のもの（例：FLUX.2 9B）は入れない。12GB VRAMに収まるか先に見積もる。
- **D（ルール）を直すとき**：PCの `CLAUDE.md` を直し、チャットのスキルは propose_skills で改善案を出して本人にカードで保存してもらう。チャッピー側に関わるルールは、チャッピーに渡す申し送り文も作る。
- **本人が決めたことは、カイゼンの名目で変えない**：使う道具の指定、声の速さを変えない、BGM・効果音なし、テロップの書式（極太明朝・エメラルド）、背景は純黒、キャラの絵柄など。変えたほうがよいと思ったら、理由をつけて提案だけする。

## 3. 記録
`logs\kaizen.md` に1本ごとに追記する。

```
## YYYY-MM-DD 動画名
- 起きたこと：（場面番号・道具）
- 原因：A〜Eのどれか＋ひとこと
- 直したこと：ファイル名と変えた値（前→後）
- 結果：測った数字や見た目の変化。標準を切り替えたかどうか
- 次に見ること：
```

記録が長くなったら、古いものは月ごとに数行のまとめにする。

## 4. 本人への報告
- 納品の返事の最後に「今回のカイゼン」を3行以内で書く：直したこと／効果／次に試すこと。
- 何も直さなかったときは「今回は直す所なし」と1行だけ。
- PCにつながっていなくて直せなかったときは、直したい所を書き残し、次につながったときに最初にやる。
