# 見せ場監督

「ここが見せ場なのに、できあがると意外としょぼい」——これを防ぐ係です。
`yakubon-medical-video-iris` の手順1（シナリオ）と手順9（確認）に割り込んで、**二度**働きます。

## なぜ見せ場ほどしょぼくなるのか

偶然ではありません。三つの理由が重なります。

1. **見せ場は一枚の絵にできない。** 平凡なカット（臓器の全体像、女の子が指さす）は一枚で完結するので絵が強い。
   見せ場は「破裂する」「詰まる」「流れが止まる」——つまり**変化そのもの**です。
   変化は静止画に描けないので、どっちつかずの絵になり、それを動かしても中途半端にしかなりません。
   **絵が弱いから動画が弱いのであって、動画化が下手なのではありません。**
2. **i2vは安全側に倒れる。** 画像から動かすモデルは構図を壊さないよう「小さく動く」方へ寄ります。
   プロンプトに dramatic と書いても、**元の構図が変わらない限り大きな動きは出ません。**
3. **尺が均等。** 「1枚3秒」で割ると山場も3秒です。BGMを入れない方針なら落差は視覚だけで作るので、
   なおさら尺とコントラストが要ります。

## 一度目：台本の段階で「山場宣言」（お金が出る前・ここが本丸）

台本ができたら、絵を1枚も作る前に宣言します。

| 決めること | 決まり |
|---|---|
| **山場はどれか** | 15場面のうち**2つだけ**。3つ以上にすると全部が平坦になります |
| **3枚で設計** | 山場は「前・**瞬間**・後」の3枚。2枚（始点→終点）では肝心の瞬間が抜けます |
| **尺** | 山場は平均の2倍（6〜8秒）。**直前のカットは2秒に詰める**（静けさで溜める） |
| **カメラを動かす** | 被写体だけ動かすのは平凡。山場は寄る・回る・突き抜ける |
| **構図の跳躍** | 山場の前後で、被写体の画面占有率を**2倍以上**変える（引き→超接写） |
| **道具** | 山場だけ Seedance 2.0 Mini／Gemini。**LTX-2.3に山場を任せない** |

決めたら台本（`script.json` など作品フォルダの台本）に `"misebasho": [7, 12]` と書き残します。
完成後の計測でこの番号を使います。

本人に見せるのは**この宣言と、山場2カットのクレジット見積もり**です。ここで承認をもらってから絵を作ります。

## 二度目：完成後に数字で測る

```bash
python3 studio/mp4/check_dynamics.py 作品\_完成.mp4 --highlight 7,12
python3 studio/mp4/check_dynamics.py 作品\_完成.mp4 --highlight 7,12 --json 作品\dynamics.json
```

ffmpegだけを使います。生成も課金もありません。

**読み方**

| 列 | 意味 |
|---|---|
| 動き | 1コマ前との差の平均。この動画の中での相対値です |
| 調子 | `止`＝ほぼ静止（0.15以下）／`静`／`中`／`動` |
| ★ | `--highlight` で指定した山場 |

**出る指摘と、その意味**

- `✗ カット7（山場）の動き … 中央値以下` → **絵からやり直す**のが先。3枚（前・瞬間・後）に描き直し、
  構図を跳ばす。絵が同じまま道具だけ替えても、たいてい同じ結果になります
- `△ 山場の尺が平均の1.3倍に届かない` → `edit.json` で尺を伸ばす（無料で直ります）
- `△ 直前のカットが静かではない` → 直前を2秒に詰める（無料で直ります）
- `△ ほぼ静止のカットが○%` → **終盤に固まっていたら要注意。**最後まで見てもらえません
- `△ 同じ調子が4連続` → 単調です。1つ詰めるか、1つ動かす

**無料で直せるもの（尺・順番・詰め）から先に手を付けます。**撮り直しは最後です。

## 撮り直しを決めるとき

- **勝手に回さない。** カット番号・何が足りないか・どの道具で・何クレジットかを表にして本人に出し、
  承認をもらってから生成します（`medical-video-motion-budget` と同じ作法）。
- 残高と見積もりを先に確認し、足りなければ止めて報告します。
- 直したら**もう一度 `check_dynamics.py` を回して**、数字が動いたことを確かめます。
  直したつもりで直っていないことがあります。

## ヒーローのお試し（Gemini と Seedance 2.0 Mini）

2026年11月から1ヶ月、冒頭ヒーローを Gemini と Seedance 2.0 Mini の両方で試しています。
**ヒーローは外から来てもかまいません。**本人が Gemini で作ったmp4を作品フォルダに置けば、
以降は普通に流れます（CoeFontの声とまったく同じ形です）。

1本作るたびに `logs\hero_ab.md` へ1行。

```
日付 | 題材 | 道具 | クレジット／費用 | 待ち時間 | 3日後の再生数 | 3日後の保存数
```

**3日後の数字まで書くのが肝です。** 出来栄えの印象で決めると、人は「最後に見たもの」と
「印象が強かったもの」に引っ張られます。表を見れば、1ヶ月後に答えは勝手に出ています。

## 参照帳（毎回やらなくてよい）

伸びている動画を見つけたときだけ、`logs\baz_references.md` に**3行**。

```
2026-11-15 | 美術系リール（結晶が割れる4秒）
効いている理由：割れる0.3秒前に完全静止。音がなくても「溜め」が効く
自分のどこに使えるか：山場の直前カットを2秒に詰める根拠
```

**リンクを貯めるのではなく、原理を抜き出して書きます。** そうすれば道具が変わっても残ります。
医療系だけでなく、美術系・自然科学系など美しい動画も見ます。隣の分野から持ってくる方が、
同じ分野で競るより効きます。

## してはいけないこと

- 山場を3つ以上にする（全部が平坦になります）
- LTX-2.3に山場を任せる
- 数字が悪いからといって、承認なしに生成を回す
- 「動きが足りない」を動画化のやり直しだけで解決しようとする（たいてい絵が原因です）
- この道具の結果だけで完成を判断する。**解剖の正しさ・テロップの読みやすさ・声との合いは
  測っていません。**最後は必ず通しで見てください
